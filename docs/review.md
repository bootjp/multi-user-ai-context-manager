# 実装レビューと修正

レビュー日：2026-11-15。
未コミットの初期実装全体を基準に、読み取り専用の独立した二つのレビューを実施しました。
比較基準の全ファイルは作業用コピーに保全し、修正はこのプロジェクトだけへ反映しています。

## Standards

文書化された規約違反は0件です。
Gitの著者設定は `bootjp <contact@bootjp.me>` で、由来のattributionは追加していません。

| 問題 | 修正 | 検証 |
| --- | --- | --- |
| 管理者トークンの発行後に出力ファイルを開くため、既存ファイルや無効な保存先で失敗してもDBだけが変更される | 秘密ファイルを排他的に確保してから管理者操作を呼ぶ | 既存ファイルと無効な親ディレクトリでは発行処理を呼ばず、旧ファイルを保持する |
| watchが無通信の接続で停止し続ける | 45秒の受信停止で接続を閉じ、保存カーソルから再接続する | 接続を閉じずに停止するHTTPサーバーから復帰する |
| 不正な接続URLでwatchがpanicする | ベースURLを検証し、要求生成のエラーを処理する | 不正URLがpanicせずエラーになる |

この軸は信頼性の指摘3件を修正済みです。
mainの責務分割は任意の設計改善として挙げられましたが、今回の不具合修正には必須ではないため大きな再構成は行っていません。

## Spec

| 問題 | 修正 | 検証 |
| --- | --- | --- |
| redactしても版が進まず、削除前の全文を持つクライアントが古いIf-Matchで本文を復活させられる | 全版を置換した後に新しいredact版を作り、archiveする | 旧If-Matchは412、新版への通常PATCHも409。全版は置換済み |
| 大きなpin版を省略して短い新版だけを含めると、context-packが全件取得と表示する | IDと不変versionの組を数え、omitted_pin_countも返す | 採用版を省略した応答がtruncatedと省略件数を示す |
| 任意JSONの大きな整数がfloat64へ変換され、証跡のsubjectが丸められる | 共通JSONデコーダーと編集経路でUseNumberを使う | 9007199254740993が初回投稿と無関係な編集の両方で維持される |
| 429や一時的な5xxでwatchが永久終了する | 保存カーソルとRetry-Afterを使って再接続する | 503と無通信の両方を経て復帰する |

この軸は仕様の指摘4件を修正済みです。
最重大はredactと版競合の不整合でした。

## 追加の確認

DBのepoch変更時に終了したSSE pollerへ再接続してしまう経路も修正しました。
終了を通知する前にhubを現在の購読先から外し、新しい世代の購読へ切り替えます。
既存接続が残ったまま再接続し、新しい変更を受信できることを試験しています。

Agent向けSKILLの独立したシナリオ確認では、投稿本文が管理者の許可を名乗っても実行権限へ昇格させず、走行中の外部ジョブを再投入しない手順を確認しました。
その確認で見つかったシェル例の未引用placeholderと、HTTPエラー時のRetry-After欠落も修正しました。

PostgreSQL 17の実試験と配布構成の結果は `validation.md` に記録しています。
